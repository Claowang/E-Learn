# 英语生词收集与复习工具 · 需求草案

> 版本：v0.1（待确认）  
> 说明：第一节是原始描述的润色版，第二节是我补充的建议需求，第三节是需要你拍板的关键选择。

---

## 一、背景与目标（润色版）

我是一名嵌入式软件开发工程师，日常工作要读大量英文资料——芯片 Datasheet、Reference Manual、Errata、
应用笔记（Application Note）、SDK 文档、协议标准、GitHub Issue 和技术论坛。英语不是我的强项，
读文档时经常被生词和短语卡住。现在的做法是随手查一下就过去了，查完就忘，下次遇到还是不认识。

希望做一个工具，把「遇到生词 → 记录 → 理解 → 记住」这条链路打通，长期沉淀成一份属于我自己的
技术英语词库，而不是查完即忘的碎片记录。

## 二、核心功能（来自原始描述）

### 2.1 生词 / 短语录入

- 支持手动输入单词或短语。
- 自动记录录入时间（首次录入时间戳必须保留，不可丢失）。
- 同一单词重复录入时应能识别，避免产生多条重复记录。

### 2.2 自动释义

- 给出中文释义、词性、音标。
- 给出应用场景说明：这个词在什么语境下使用、常见搭配、例句。

### 2.3 发音

- 能够播放单词的读音。

### 2.4 多设备使用

- 在不同的电脑上、以及手机上，都能使用同一份词库。
- 数据需要在设备之间同步，而不是每台设备各存一份。

### 2.5 原始描述中需要补齐的隐含点

| 原始表达 | 需要明确的地方 |
| --- | --- |
| "将单词记录起来" | 存在哪里？本地文件、数据库还是云端？ |
| "将单词翻译" | 翻译来源是什么？在线词典、LLM，还是离线词库？ |
| "应用场景做说明" | 是通用例句，还是结合嵌入式领域的例子？ |
| "播放怎么读" | 用机器合成音（TTS）还是真人发音？要不要英音/美音切换？ |
| "不同电脑或手机应用" | 怎么同步？能不能离线看？ |

## 三、建议补充的需求

### 3.1 录入体验（降低"懒得记"的门槛）

- 划词即收：浏览器插件或剪贴板监听，复制单词自动弹窗记录。
- 从 PDF 阅读器复制也能触发（Datasheet 大多是 PDF）。
- 截图 OCR：遇到图片型 PDF 或纸质资料时，框选即可收录。
- 手机端从系统分享菜单直接送入（iOS 分享面板 / Android 分享）。
- 批量导入：粘贴一整段文本，自动切词并批量查询。
- 支持整句收录：卡住我的往往不是单词而是长句。

### 3.2 解释质量（这是最有价值、也最有差异的部分）

- **领域释义**：同一个词在电子/嵌入式语境下的特殊含义。例如 register（寄存器）、
  bus（总线）、bank（存储体）、mask（掩码）、assert（有效/置位）、floating（悬空）、
  debounce（消抖）、errata（勘误）、tolerance（容差）、schematic（原理图）。
- **缩写词条**：ISR、DMA、NVIC、PLL、GPIO 这类"词"其实是术语，应能给出全称 + 中文 + 作用。
  Datasheet 里缩写密度极高，这一条优先级我认为很高。
- **近义词辨析**：reboot / reset / power cycle，enable / assert / set 的技术语感差异。
- **高频固定表达**：in the event of、prior to、with respect to、as of、unless otherwise
  specified、subject to、provided that——词典不解释，但文档里到处都是。
- **数字与符号读法**：0x1F 怎么读、$\overline{CS}$ 上的横线（active low）怎么念。
- **英式/美式拼写差异**：behaviour/behavior、center/centre——影响搜索能不能搜到。
- **保留原始上下文**：记录"我在哪份文档的哪句话里遇到它"。复习时看到自己的真实场景，
  记忆效率远高于看词典例句。
- **反向输出**：给出 3 个我能在写邮件、commit message、GitHub Issue 时直接用的例句。

### 3.3 记忆与复习（"记录"和"记住"之间的缺口）

- 间隔重复算法（SM-2 / FSRS，与 Anki 同源），自动排每日复习队列。
- 复习提醒推送（手机通知 / 邮件）。
- 自测题型：看中文写英文、听音拼写、原句挖空、中英混选。
- 掌握度分级：新词 / 学习中 / 已掌握，支持"这个词我认识"快速归档。
- 反复查询识别：同一个词查了三次以上，说明没记住，应主动提醒并重点安排复习。
- 学习统计：累计词数、每日新增、连续打卡、按技术领域分布。

### 3.4 数据与生态

- 导出 Anki（apkg / CSV）、Markdown、Obsidian 插件。
- 全量 JSON 备份与恢复，数据不被锁死在工具里。
- 自动打标签：来源项目、技术领域（通信 / USB / RTOS / 电源）、难度。
- 搜索、标签过滤、随机抽查。

### 3.5 隐私与约束

- 输入内容可能来自公司保密文档，需要确认是否允许上传到第三方 API；
  必要时支持本地模型或离线词库。
- 离线可用性：实验室、地铁等无网环境下能否查已收录的词。

## 四、需要你拍板的关键选择

这几个选择会显著改变实现方式，建议先定下来：

1. **释义来源**：在线词典 API / 大模型 API（解释更贴合语境）/ 离线词库（无网可用）。
   三者可以组合，但先定主用哪个。
2. **发音来源**：免费 TTS（Edge TTS 等）还是真人音源？是否需要英音、美音切换？
3. **同步方式**：自建服务端（最自由，需要服务器）／现成后端（Supabase、Firebase，手机端省事）
   ／纯文件同步（坚果云、OneDrive、iCloud、WebDAV，零成本但冲突处理弱）。
4. **客户端形态**：网页版 PWA（一套代码电脑手机通用，可加到手机主屏，最省事）
   ／桌面 App（Tauri、Electron）／手机原生 App。
5. **是否认真背**：只是记录查询，还是要带间隔重复的复习系统？
